# TradeMagic MT5 Bridge 0.10.1

Fixes a shared clock dependency that could block all instruments when the preferred clock symbol stopped receiving fresh ticks. Automatic clock verification now uses independent advancing samples from the preferred symbol and other non-custom symbols already selected in MT5 Market Watch. Stale sources do not cancel unexpired verified offset evidence, and do not renew it. Each trading command retains its own symbol-specific freshness/spread checks. If all clock sources become unavailable beyond the evidence lifetime, the profile still blocks. Time-trust failures still block; a changed offset requires advancing evidence and operator review. Diagnostics expose the source of the latest verified offset and the latest observation warning separately from clock readiness.

Upgrade from 0.10.0 using Reuse existing configuration. The installer preserves account settings and journals. The Windows/backend clock-estimation threshold is unchanged; this release addresses stale-instrument isolation.

## Initial public release: 0.10.0

Initial public Windows x64 release, supporting explicitly selected Demo and Live accounts. Existing Demo profiles and journals migrate as Demo and cannot be silently repurposed for Live execution.

- State-aware Edit, Start, Stop and Pause/Resume controls, including pending requests, connection tests and authoritative state refreshes.
- Full agent shutdown hidden when Windows startup manages it; quitting only the configuration UI remains available.
- Automatic broker-clock monitoring with persisted forward evidence and conservative handling of changes/gaps.
- Account/terminal identity checks, backend-owned sizing and mapping, lease/ownership fences, durable command deduplication and evidence-based reconciliation.
- Branded reinstall with Reuse/Fresh choices, retained journals, verified backups, bounded taskbar cleanup and removal of verified obsolete payloads.
- Default history scope starts with the Bridge period when the backend supplies no explicit date; existing bounded history settings remain intact.

Native acceptance has exercised one Demo account: market open/close, pending placement/modification/cancellation, SL/TP changes, partial close, terminal restart, backend interruption and completed-command worker restart. Live-account environment matching and protection against account/environment changes are covered by deterministic adapter tests; no live-money trade was submitted during release preparation. Fresh-install and multiple-account/provider rehearsals remain planned. The public release will be used for the continuing week-long run.

This installer is unsigned. Third-party component notices and license texts are included in the installation's third-party directory. Historical account imports predating the Bridge period are outside the requested default scope. Unknown clock-history gaps are reported rather than fabricated.
